# 効果的なIDSメタデータのガイド

IDSは人間とコンピューターの両方が読めるように設計されています。**要件** をコンピューターに正確かつ精密に記述することが重要であるのと同様に、**要件** の目的、意図、および有用性をIDSの受信者に説明することも同様に重要です。これは**要件** メタデータを入力することによって実現されます。モデル作成者、設計者、エンジニア、クライアント、コンサルタント、その他の関係者が、なぜ情報が必要なのか、誰にとって有益なのか、いつ使用されるのかを明確に理解することで、要求条件が効果的に満たされることを保証できます。

## IDSメタデータ

各`.ids`ファイルには、IDS内に記載されたすべての**要件** に共通する基本メタデータがあります。

| copyright   | IDSの著作権者                                                                                                                                                                                                                                                                                                                                                                           | "株式会社サンプル" または "政府機関X"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| version     | IDSのバージョン、行われた変更を追跡するためのもの。セマンティックバージョニングが推奨され、バージョニングはX.Yの命名スキームに従い、Yはメタデータ、説明、またはスペルエラーの変更などの軽微な変更を表し、Xは以前のバージョンで合格または不合格だったモデルが異なる結果を生成する可能性がある大きな変更を表します。 | "1.0" または "2.1"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## 要件メタデータ

各**要件** には、目標とその達成方法の指示を説明するためのメタデータがあります。

| 名前         | 説明                                                                                                                                                                                                                                                           | 例                                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| name         | 指定されている情報の短い名前                                                                                                                                                                                                                                   | "壁タイプの命名規則" または "コンクリート数量積算寸法"                                                                                                 |
| ifcVersion   | 期待されるIFCバージョン。選択肢: "IFC2X3"、"IFC4"、"IFC4X3_ADD2"                                                                                                                                                                                            | "IFC4X3_ADD2"                                                                                                                                             |
| identifier   | 明確で曖昧でない識別のため、より簡単な追跡、参照、および報告を可能にします。IDSファイル内で一意である必要があります。                                                                                                                                           | "SP01"、"Fire-001"、"5b1b0426-a21d-4ee9-9b53-e9b7827690a7"                                                                                                |
| description  | なぜ要求条件がプロジェクトにとって重要なのかを説明します。説明を読む人は、なぜその情報が価値を提供するのか、どのワークフローの実現に役立つのか、要求条件が満たされない場合にどのようなプロジェクト上の利益が犠牲になるのかを理解する必要があります。 | "コスト算定、詳細設計、建物改修に大きな影響を与える基本的な特性は、建設リスクを最小限に抑えるために含める必要があります。"          |
| instructions | 誰が情報を提供する責任があるか、および命名規則がどのように機能するか、適切な値を選択する方法、またはエッジケースで何をすべきかに関するガイドラインなど、それがどのように達成されるかの詳細に関する指示を提供します                                         | "建築家とコードコンサルタントがこの情報を提供する責任があります。複数の値がある場合、支配的な値を示さなければなりません。" |
